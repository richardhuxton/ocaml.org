<h2><a href="https://anil.recoil.org/news.xml#the-uk-openness-report-from-openuk" class="anchor" aria-hidden="true"></a>The UK Openness report from OpenUK</h2>
<p><a href="https://openuk.uk">OpenUK</a> published their excellent <a href="https://openuk.uk/wp-content/uploads/2026/07/AI-Openness-Report-July-2026.pdf">AI Openness report</a> this month. I'm in there with a fireside chat on open foundation models like <a href="https://anil.recoil.org/projects/tessera">TESSERA</a>, and a followup to conversations I started with Amanda Brock at the <a href="https://anil.recoil.org/notes/india-ai-summit">Indian AI summit</a>:</p>
<blockquote>
<p>Openness matters here because a foundation model of the planet that you
cannot inspect, cannot reproduce, and cannot train yourself would be a
dangerous thing to derive social land-use policy from. The people who need it
most -- conservationists, smallholder farmers, government agencies across the
Global South -- are the least likely to be able to pay big money for
proprietary access.
<cite>-- me in the <a href="https://openuk.uk/wp-content/uploads/2026/07/AI-Openness-Report-July-2026.pdf">OpenUK AI Openness: 3 Years on From Llama 2</a>, July 2026</cite></p>
</blockquote>
<p>'Openness' is a little odd these days in that we have to manage community more these days than adoption. For example, every <a href="https://anil.recoil.org/notes/first-tessera-hackathon">TESSERA hackathon we've run</a> has filled to capacity, and the <a href="https://github.com/ucam-eo/geotessera">geotessera</a> issue tracker is flowing with issues, so people are certainly using our output!</p>
<p>But then every single user I talked to at the <a href="https://anil.recoil.org/notes/cng-london-2026">CNG summit recently</a> was coding at high speed with AI assistance and not really reading the docs directly, and so getting people to talk to each other (mentoring, trading tips of the craft, understanding how it all works, etc) takes much more effort than it used to before the advent of Claude. We're in a new world of open source...</p>

<h2><a href="https://anil.recoil.org/news.xml#prototyping-the-evidence-tap-website-with-an-agent" class="anchor" aria-hidden="true"></a>Prototyping the Evidence TAP website with an agent</h2>
<p>I started working on <a href="https://anil.recoil.org/notes/2026w29">a website for Evidence TAP</a> last week, and put up a work-in-progress site at <a href="https://evidencetap.exe.xyz/">evidencetap.exe.xyz</a> and I hope to push it live next week once the content takes shape. We've had a staggering number of requests from policymakers who are interested in our approach, and so the site gathers up the basic idea of living evidence databases that continuously ingest, screen, appraise and extract from the literature, with every claim traceable back to its source. This began with the <a href="https://anil.recoil.org/projects/ce">Conservation Evidence</a> team, and we're moving next into an education strand with <a href="https://www.educ.cam.ac.uk/people/staff/gibson/">Jenny Gibson</a> and Mélanie Gréaux.</p>
<h3><a href="https://anil.recoil.org/news.xml#trying-out-exedev" class="anchor" aria-hidden="true"></a>Trying out exe.dev</h3>
<p>As an experiment in collaborative agent prompting, I've been using <a href="https://exe.dev">exe.dev</a>, which gives you a pool of CPU, RAM and disk and lets you spin up as many persistent VMs as you like. The lack of ephemereality is useful when dealing with authentication and state, i.e. when doing agentic programming.</p>
<p>Their inhouse web agent is called 'Shelley' which also has a mobile app that's just been released.  My only gripe is that Shelley can't seem to interact directlly with Claude Code, and it runs on usage credits rather than being able to use a subscription account like the one I already pay for. I suspect this will get resolved as these agent platforms mature, and I'm on the <a href="https://x.com/Kimi_Moonshot/status/2078855608565207130">Kimi K3 waitlist</a> if it doesnt!</p>
<p>Outside of agentic stuff, exe.dev also has really useful protocol proxies like an inbound HTTPS tunnel that takes care of certificates, and also a very good CLI. It's a very pleasant experience to anyone familiar with Unix-style environments.</p>
<h2><a href="https://anil.recoil.org/news.xml#ocaml-and-oxcaml-releases" class="anchor" aria-hidden="true"></a>OCaml and OxCaml releases</h2>
<p>A year's worth of changes went into <a href="https://github.com/ocaml-multicore/eio/releases/tag/v1.4">Eio 1.4</a>, which is out thanks to <a href="https://roscidus.com">Thomas Leonard</a> and <a href="https://notes.roscidus.com/2026/07/24/">his excellent changelogging</a>. This website is now running on Linux 7.x and using my <a href="https://github.com/ocaml-multicore/eio/pull/884">uring socket/bind/listen conversion </a>, and the Evidence TAP literature downloader (more on that soon!) uses the <a href="https://github.com/ocaml-multicore/eio/pull/850">ftruncate/fdatasync</a> and other filesystem optimisations too.</p>
<p>I also cut a minor <a href="https://github.com/ocaml/opam-repository/pull/30339">cohttp 6.2.2 release</a> to be compatible with the new Eio, which is winding its way through opam-repository. Eio 1.4 changed the <code>getaddrinfo(3)</code> into an exception and to include the query in the error message.</p>
<h3><a href="https://anil.recoil.org/news.xml#improving-oxcaml-support-and-the-claude-skill" class="anchor" aria-hidden="true"></a>Improving OxCaml support and the Claude skill</h3>
<p>I also cut a <a href="https://github.com/realworldocaml/mdx/releases/tag/2.6.0">mdx 2.6.0</a> release which I made compile with <a href="https://anil.recoil.org/projects/oxcaml">OxCaml</a>. Unfortunately you can't actually use it yet, because this new version needs an explicit dependency on <code>unix</code> and the <a href="https://github.com/ocaml/dune/pull/15592">fix for that in dune</a> is merged but not yet released. We'll have to wait for dune 3.25 before its fully usable, but that's already <a href="https://github.com/ocaml/dune/issues/15593">under preparation</a>!</p>
<p>Once that's done, getting Eio compiling with the latest <a href="https://github.com/oxcaml/opam-repository/pull/54">OxCaml minus39 release</a> will be much easier thanks to mdx compiling out of the box. I've also published a <a href="https://github.com/avsm/ocaml-claude-marketplace/commit/90cd8e910f755527d2a6a63b6eae6dd748adbd4b">comprehensive update</a> of my <a href="https://github.com/avsm/ocaml-claude-marketplace">ocaml-claude-skills</a> marketplace (which seems to be accruing users).  I'm going to do a massive update of my monorepo over to minus39 in the next week or two, which should be a good test of this Claude Fable skill! Feel free to send PRs if you've got improvements to my skills.</p>
<h3><a href="https://anil.recoil.org/news.xml#eio-in-forester" class="anchor" aria-hidden="true"></a>Eio in Forester</h3>
<p>I'm now also looking at Windows support rather glumly (no matter how much I try, I
can't get a good CRLF conversion environment). The reason I'm
investigating it is that we have a REAL USER I KNOW in the form of <a href="https://jonmsterling.com">Jon Sterling</a> !</p>
<p>In Jon's recent <a href="https://www.jonmsterling.com/2026-W28/">weeknotes</a> he mentioned progress towards Forester 6.0 (which Kento Okura is pushing along with support from Tarides and the OCaml Software Foundation). <a href="https://patrick.sirref.org">Patrick Ferris</a> chimed in on <a href="https://eeg.zulipchat.com/#narrow/channel/522690-Blogs/topic/JMS.20Weeknotes.202026-W28/with/611607207">our Zulip thread</a> with some tips about cutting out a <code>stat</code> per file. Patrick knows <a href="https://tangled.org/@jonmsterling.com/ocaml-forester">Forester</a> well, having become familiar with its directory scanning logic while writing his own <a href="https://github.com/patricoferris/graft">graft</a> fork/variant which his website runs on.</p>
<p>I also integrated a few quality-of life utilities like the <a href="https://github.com/ocaml-multicore/eio/pull/894">null sink</a> into Eio 1.4 which a future Forester can hopefully use. Temporary files and directories are next on my list, as I've discovered <code>O_TMPFILE</code> on Linux that allows for the creation of anonymous fds.</p>
<p>I asked Jon whether he ships Windows binaries and he said it has long been a goal, blocked mostly on how Forester handles paths. After I achieved the milestone of working out how to map the <code>\</code> key onto my Windows machine, I started understanding modern Windows paths. Kento's <a href="https://github.com/ocaml-multicore/eio/pull/738">pathname PR</a> is a start, but we'll likely need to have Windows and POSIX specific pathname logic that's separate.</p>
<h2><a href="https://anil.recoil.org/news.xml#on-matters-of-nature" class="anchor" aria-hidden="true"></a>On matters of nature</h2>
<h3><a href="https://anil.recoil.org/news.xml#conservation-versus-ecology" class="anchor" aria-hidden="true"></a>Conservation versus ecology</h3>
<p><a href="https://aneeshnaik.github.io/">Aneesh Naik</a> started <a href="https://eeg.zulipchat.com/#narrow/channel/522690-Blogs/topic/APN.20weeknotes.202026.2F07.2F20/with/612517496">an interesting thread</a> on our Zulip off the back of <a href="https://www.aneeshnaik.com/blogposts/20260720_weeknotes_2026_29.html">his weeknote</a> about whether nature should be monitored at all.
His thought came from a colloquium in the CCI by <a href="https://en.wikipedia.org/wiki/Hugh_Possingham">Hugh Possingham</a>, who argued that one should only pursue a nature monitoring project when there is a specific on-the-ground action that will follow from it. However, a great deal of what we now know about effective conservation comes from people who kept their monitoring schemes running long past the point where they had any planned interventions left! The <a href="https://doi.org/10.1098/rspb.2025.2527">paper behind the talk</a> lays out many reasons for monitoring as a checklist and a theory of change, and does include plain societal curiosity!</p>
<p>Much of the <a href="https://anil.recoil.org/projects/rsn">remote sensing</a> work going on here is really <em>ecological</em> monitoring rather than <em>conservation</em> monitoring: the former is aimed at understanding an ecosystem itself and the latter at establishing the counterfactual impact of some intervention. Ecology does have a close sister discipline of conservation with some extremely vital imperatives attached, and a <a href="https://anil.recoil.org/notes/nas-rs-biodiversity">temporal urgency</a> with respect to human actions.</p>
<h3><a href="https://anil.recoil.org/news.xml#ranger-patrols-get-funding" class="anchor" aria-hidden="true"></a>Ranger patrols get funding</h3>
<p><img src="https://anil.recoil.org/images/ai4pg-2026-winners.webp" alt="%rc" title="The eleven AI4PG 2026 grant winners, in excellent company from Korea to Timor-Leste">
Huge congratulations to <a href="https://charlesemogor.com">Charles Emogor</a>, who has landed one of the highly contended <a href="https://www.ai4pg.com/grants/ai4pg-2026">AI4PG 2026 fast grants</a> for our work on optimising ranger patrol deployment in sub-Saharan Africa. The project is with <a href="https://www.zoo.cam.ac.uk/directory/professor-rob-fletcher">Rob Fletcher</a>, Lingkai Kong at Harvard and Inaoyom Imong at the Wildlife Conservation Society in Nigeria, and eleven proposals were selected from 135 submissions across 38 countries.</p>
<p>This funds the next stage of the work Charles has been driving on <a href="https://anil.recoil.org/ideas/validating-anti-poaching-predictions">validating anti-poaching predictions with ranger insights</a> and <a href="https://anil.recoil.org/ideas/mapping-hunting-risks-for-wild-meat">mapping hunting risks</a>. The core problem is that patrol-collected data is biased since rangers only see what they walk past, and so a map of "where poaching happens" is often really just a map of "where rangers went". Charles plans to combine ranger patrols from 2016 onwards with GPS data collected from 120 hunters across eight communities, model the two independently, and use the mismatch to build a bias-correction layer over three protected areas in southeast Nigeria.</p>
<p>Given that <a href="https://thedocs.worldbank.org/en/doc/fa250077ab87b35d0451b82653e0f4f3-0320072025/original/GWP-2025-Analysis-of-International-Donor-Funding-to-Combat-IWT-2010-2023.pdf">billions have been spent on anti-poaching globally</a> since 2010, even modest improvements in where the patrols go are worth a great deal!</p>
<h2><a href="https://anil.recoil.org/news.xml#fun-links" class="anchor" aria-hidden="true"></a>Fun links</h2>
<ul>
<li>Diamond prices have crashed to <a href="https://finance.yahoo.com/markets/commodities/articles/diamond-prices-plunge-lowest-levels-175618297.html">their lowest level this century</a>. Even lab-grown stones have fallen by ~88% since January 2020. Meanwhile <a href="https://tradingeconomics.com/commodity/brent-crude-oil">Brent crude</a> touched $120 in April and is still hovering near $97, so this is a year in which the carbon is dear and carbon crystals are cheap. Go figure.</li>
<li><a href="https://www.cst.cam.ac.uk/people/zf281">Frank Feng</a> found a great paper that does to the Moon roughly what we've been doing to Earth with <a href="https://anil.recoil.org/projects/tessera">TESSERA</a>. <a href="https://arxiv.org/abs/2607.22408">LunarFM</a> is a multimodal foundation model that assimilates observations from six instruments across three lunar missions and maps 18 input channels into a shared embedding space. This then allows very similar functionality to what we have in tools like <a href="https://tee.cl.cam.ac.uk">TEE</a> with similarity search, few-shot resource mapping, mineral abundance regression and geological unit classification.  There's also efforts ongoing for Mars via <a href="https://doi.org/10.1029/2025JH000827">a domain-specific vision foundation model</a> trained with self-supervision on millions of Mars Reconnaissance Orbiter Context Camera images.</li>
<li>Closer to home, <a href="https://arxiv.org/abs/2607.19069">Delineate Anything v2</a> is going to be very useful for <a href="https://anil.recoil.org/papers/2026-tessera-v2">TESSERA v2</a> evaluation. It's a global field boundary delineation model with an accompanying 73m dataset spanning 61 countries, and a benchmark covering 100 countries for zero-shot generalisation. Field boundaries are a pretty tough test for a geospatial representation since it needs both the texture of the crop and often a sub-10m scale. Looking forward to trying this out later in the year.</li>
